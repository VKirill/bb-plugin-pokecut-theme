## Three defects on the owner's live BB with 0.5.17 (tree scrolling is fixed and verified)

### 1. Проект overlaps New thread when the top row also holds Back/Forward (browser QA @thr_9p43n3x5s6, 1440px)
Rail right 64. Проект (`.pf-tree > button:first-child`, absolute, anchored to `--pk-rail`) 72..163.8. New thread (`margin-left: auto`) 140.5..248, Back 252..280, Forward 284..312. Row content width 240 is not enough for Проект (92) + New thread (108) + arrows (60) + gaps; Проект covers New thread's «+» icon. In the owner's macOS app the arrows live in the window chrome row, so the row there has only New thread and both fit.
Fix: when the top row contains the Back/Forward buttons (detect with `:has()` on `[data-testid="app-sidebar-top-reserve-row"]`, e.g. `:has(button[aria-label^="Back"], button[aria-label^="Назад"])` — check BB's actual aria-labels/test ids in the theme's earlier notes; if unknown, match `:has(> * + * + *)`-style counts is NOT acceptable, use aria-label prefixes Back/Forward/Назад/Вперёд), switch Проект to an icon-only square 32x32 pill (hide the ::after label) so it ends at ≤ 104 and New thread (140.5..248) is clear by ≥ 8px. Also guarantee in all cases: New thread's left ≥ Проект's right + 8 (e.g. give the top row `padding-left` equal to the Проект width + 8 when the label is shown; in icon-only mode 32 + 8) so they can never overlap; New thread keeps its full label.

### 2. Top-left join: a different gray strip next to the content panel's corner (owner screenshot)
At the top of the sidebar, right next to the content panel's rounded top-left corner, the sidebar area left of the corner is gray (shell-like) while the part under the corner is the light surface color — a visible two-tone strip. Cause: BB's top row `div[data-testid="app-sidebar-top-reserve-row"]` keeps BB's own `bg-sidebar` background (rgb 237), while 0.5.9 only made `[data-sidebar="header"]`, `[data-sidebar="content"]`, `[data-sidebar="footer"]` transparent. Fix: in the desktop block make `[data-testid="app-sidebar-top-reserve-row"]` and `[data-testid="app-sidebar-body"]` (and any other direct child wrapper of `[data-sidebar="sidebar"]` except the icon rail `[data-testid="app-nav-rail"]`, which keeps its tint) `background-color: transparent`, so the whole sidebar surface is one color up to and under the content panel's corner.

### 3. Bottom: an artifact sticks out below the content panel's bottom-left corner (owner screenshot)
Just left of the content panel's bottom-left corner a light rectangle ~25px wide runs from the panel's bottom edge down to the window bottom (through the 12px bottom gutter). Most likely BB's sidebar resize handle `[data-sidebar="rail"]` (shadcn SidebarRail: `absolute inset-y-0 z-20 w-4 ... group-data-[side=left]:-right-4`, full panel height, hover background), or the `[data-sidebar="gap"]` element, painting past the sidebar surface's bottom (the surface ends 12px above the window bottom, the panel does not). Fix: in the desktop block constrain the resize handle to the surface: `[data-variant="sidebar"][data-side="left"] [data-sidebar="rail"] { top: 0; bottom: var(--pk-gap); background: transparent; }` (keep it functional for resizing; hover may show only a thin line inside the surface), and make sure `[data-sidebar="gap"]` paints nothing (`background: transparent`). If the handle is not the culprit, check any element inside `[data-side="left"]` whose rect extends below the surface bottom and clip it (the panel has `overflow: visible` for the tuck — do not change that; clip the element itself).

Keep everything else (tree scrolling: never set overflow on `[data-sidebar="content"]`; panel top untouched; phone rules unchanged). Version 0.5.18. Tests: assert the top-reserve-row transparent rule, the rail handle bottom rule, and the :has() icon-only rule for Проект.
